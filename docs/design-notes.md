# Заметки о проектировании

Здесь собраны проверенные факты об API Stepik, принятые решения и замысел редакторского процесса. Документ сжат из прежнего `plan.md` (версия от 2026-09-08 есть в истории Git). Порядок работ и статусы ведутся в [ROADMAP.md](ROADMAP.md).

Все числа в примерах ниже условные, если рядом не указано «проверено».

---

## 1. Что мы строим

Не отдельную программу «Stepik Lesson Verifier», а **рабочее пространство автора курса**. В нём ИИ вместе с автором проектирует, пишет, проверяет и улучшает курс, опираясь на опубликованный материал Stepik и реальные данные учеников. Проверка урока — лишь одна из функций этой среды.

```text
                     AI COURSE WORKSPACE (Claude / OpenCode)
              ┌─────────────────┼──────────────────┐
         файлы курса          skills           Stepik MCP → Stepik API
              └─────────────────┼──────────────────┘
                              модель
                ┌───────────────┼───────────────┐
             CREATE           REVIEW          REVISE
          написать урок    проверить урок   переработать
```

Для локальных клиентов MCP работает через stdio, поэтому публичный сервер, туннели и HTTPS не нужны. Удалённый режим нужен только веб-чатам (см. этап 7 в [ROADMAP](ROADMAP.md)).

## 2. Решения

### Действуют

| Дата | Решение |
| --- | --- |
| 2026-09-06 | Stepik хранит опубликованную версию, локальный Markdown — рабочую версию автора. Они могут различаться |
| 2026-09-06 | Загрузчик никогда не перезаписывает локальные файлы и не обращается к API, если файл уже есть |
| 2026-09-06 | Комментарии, статистику, решения и отзывы загружаем только по явному запросу, отдельно от текста урока |
| 2026-09-06 | Стабильные имена папок: `course-<id>`, модуль `NN-название-<section_id>`, урок `NN.NN-lesson-<id>.md` |
| 2026-09-08 | Один собственный skill `stepik-course-editor` вместо набора чужих; начинаем с REVIEW |
| 2026-09-23 | **Публикация через ИИ стала целью.** Запись появляется после формата без потерь и сначала только на тестовом курсе |
| 2026-09-23 | Поддерживаем **Claude и OpenCode** на равных; правила агентов в `AGENTS.md`, для Claude Code — `CLAUDE.md` с `@AGENTS.md` |
| 2026-09-23 | Полная загрузка курса стала целью этапа 2 (раньше сохраняли только выбранные уроки) |

### Пересмотрены

| Было | Стало |
| --- | --- |
| Stepik MCP только читает, публикует автор вручную | Безопасная публикация через plan → diff → подтверждение → apply |
| Не копируем все уроки в Markdown | Скачиваем весь курс без потерь, чтобы его можно было собрать обратно |
| Удалённый MCP не нужен | Остаётся на потом (этап 7), для веб-чатов |
| OpenCode как единственная оболочка | Любой MCP-клиент; проверяем Claude Code, Claude Desktop и OpenCode |

### Пока не делаем

- собственный GUI и отдельное desktop-приложение;
- десятки чужих skills;
- Orca и сложную многоагентную оркестрацию: хватает одного агента, который при необходимости вызывает второго; Orca понадобится только для настоящих очередей, DAG задач и параллельной работы агентов;
- собственную базу данных;
- туннели и публичный сервер.

## 3. Проверенные факты об API Stepik

### 3.1. Авторизация

OAuth-приложение Stepik с типом клиента **Confidential** и grant type **Client credentials**. Токен выдаётся от имени владельца приложения, поэтому доступ к авторским данным (`step-sources`, решения) есть только к курсам, где этот аккаунт — автор или преподаватель. Ответ 403 чаще всего означает, что прав на курс нет.

Запрос по списку ID (`ids[]`) ограничиваем 20 штуками, иначе Stepik отклоняет слишком длинный запрос.

### 3.2. Задачи на программирование

Реальная структура `step-sources`:

- `block.options.code_templates` — шаблоны решения по языкам;
- `block.options.samples` — открытые примеры;
- `block.source.code` — **строка** с авторским checker-кодом, а не объект;
- `block.source.test_cases` — авторские тесты.

Для проверки заданий и формата без потерь нужны ещё: header и footer, настройки выполнения, лимиты времени и памяти.

### 3.3. Комментарии (проверено 2026-09-06)

Фильтр `comments?step=...` не документирован и обрезал выдачу. Документированный фильтр `target` возвращает ещё и вкладку «Решения». Поэтому основные обсуждения загружаются через proxy:

```text
step.discussion_proxy → discussion-proxies.discussions → comments по ID → ответы по ID из replies
```

Загружаются все комментарии и ответы основного обсуждения, без вкладки решений и без лимита. Запросы идут пакетами, авторы подгружаются без повторов. Неполные данные дают явную ошибку, а не «комментариев нет».

Замер на уроке `2498212`: 10 комментариев с ответами на 6 шагах, 6 GET-запросов, 6,5 секунды.

### 3.4. Статистика урока (проверено 2026-09-06)

Все показатели берутся из объекта `lesson`:

- `viewed_by` — просмотры по данным Stepik. Уникальность просмотров не подтверждена, поэтому долю завершивших не считаем;
- `passed_by` — сколько студентов полностью прошли урок;
- `time_to_complete` — в **секундах** (так считает официальный Android-клиент), минуты получаем делением на 60. Stepik называет это средним временем, но формула и выборка не подтверждены.

`course_id` только проверяет, что урок входит в курс; статистику по ученикам курса он не фильтрует. Поля `unit` не подменяют показатели урока. Значения `null`, отсутствующие и некорректные поля помечаются как недоступные; нули сохраняются.

Реальный ответ для урока `2498212` курса `266999` (unit `2536151`): `viewed_by = 2`, `passed_by = 2`, `time_to_complete = null`. У всех четырёх уроков секции `734150` время равно `null`. С интерфейсом преподавателя значения ещё не сверены.

Источники: [справка Stepik о статистике уроков](https://help.stepik.org/article/54814), [схема lessons](https://stepik.org/api/docs/api-docs/api/lessons), [схема units](https://stepik.org/api/docs/api-docs/api/units), [официальный Android-клиент](https://github.com/StepicOrg/stepik-android/blob/a92eb8e6fb9d561150379352c297e7e382de53e1/app/src/main/java/org/stepik/android/view/lesson/ui/delegate/LessonInfoTooltipDelegate.kt).

### 3.5. Не подтверждено

- **Статистика задания.** Доля верных попыток — не доля решивших учеников: один человек делает несколько попыток. Для выводов об учениках нужны данные по уникальным пользователям и подтверждённый знаменатель.
- **Оценки и реакции шагов.** Какие endpoint существуют (`step-ratings`, `step-reactions`, `step-votes`) и что значат их поля, не проверено.
- **Отзывы о курсе.** Полнота выдачи и сводные оценки (`course-review-summaries`) не проверены.
- **Неверные решения.** Имена, email и user_id не выводятся, но сам текст решения может содержать персональные данные.

## 5. Редакторский процесс

Это замысел этапа 4 [дорожной карты](ROADMAP.md). Во всех режимах основа — локальный Markdown; аналитика подключается только по явному запросу.

### CREATE — написать урок

«Напиши урок 6.3»:

1. прочитать план курса, правила и текущее состояние;
2. прочитать нужные предыдущие уроки, а если их нет локально, скачать;
3. определить, что ученик уже знает;
4. составить структуру, написать урок и задания;
5. проверить код и сделать самопроверку;
6. сохранить новый Markdown в папке модуля без выдуманных ID Stepik.

### REVIEW — проверить урок

«Проверь урок 5.2»:

1. открыть локальный `05.02-lesson-2498212.md`, а если его нет, сохранить через `stepik_cache_lesson`;
2. прочитать план и правила, при необходимости предыдущий контекст;
3. проверить методику, код, задания и повторы;
4. выдать отчёт, не меняя урок.

Для каждого замечания нужны место, проблема, основание, последствия для ученика, предлагаемая правка и степень уверенности. Число замечаний не должно быть обязательным.

### REVISE — переработать

Локальный урок, правила курса, нужный предыдущий урок и указания автора превращаются в правки того же файла. ID шагов сохраняются, несвязанные фрагменты не трогаются.

### Анализ задачи

«Проверь задачу 8 урока 5.2» в расширенном режиме: условие, шаблон, тесты, успешность, попытки, неверные решения и комментарии → диагноз. Пример вывода: «Проблема не в сложности алгоритма: многие не понимают, что `pages` — число страниц, а последняя страница имеет индекс `pages - 1`. Предлагаю добавить перед задачей один визуальный пример».

## 6. Файлы контекста и разделение памяти

| Файл | Что хранит |
| --- | --- |
| `AGENTS.md` | Как работать агенту. Создаётся загрузчиком |
| `COURSE_PLAN.md` | Куда идёт курс: модули и темы |
| `COURSE_CONTEXT.md` | Постоянные знания: аудитория, терминология, соглашения, архитектурные решения учебного проекта |
| `COURSE_STATE.md` | Над чем работаем сейчас |
| `DECISIONS.md` | Почему приняты важные решения (только согласованные) |
| `rules/` | Правила текста, структуры урока, заданий, кода, проверки |
| `sessions/` | Отчёты проверок и handoff последних сессий |
| Уроки в папках модулей | Редактируемые рабочие версии и черновики |
| `.course.json`, `COURSE_MAP.md` | Снимок структуры и карта, генерируются загрузчиком |
| Stepik | Опубликованная версия |

**Handoff.** После большой сессии сохраняется короткая записка: что сделали, что решили, какие файлы изменили, что проверили, что осталось и какой следующий шаг. Новая сессия читает `AGENTS.md`, контекст, текущее состояние и последний handoff, а не сотни старых сообщений.

**Перенос знаний из GPT Projects.** Переносится не интерфейс, а знания: файлы проекта идут в папку курса, инструкции проекта — в `AGENTS.md` и `rules/`, важные решения из старых чатов — в `COURSE_CONTEXT.md` и `DECISIONS.md`. Сырые чаты можно положить в архив, но модели их не загружать: нужна выжимка актуальных решений, а не архив переписки.

## 7. Независимый рецензент

Идея: «маленькая редакция учебника». Основная модель пишет и правит урок, а модель другой семьи ищет логические разрывы, повторы, слабые объяснения, ошибки кода и недостатки заданий. Сама она ничего не меняет и не публикует.

Кандидат для первого эксперимента — DeepSeek V3.2 через OpenRouter. Перед подключением нужно проверить актуальную доступность, ID модели, тарифы, контекст и поддержку инструментов. Рецензент должен сам читать Stepik через MCP, а не полагаться на пересказ. Эксперимент проводится на одном уроке: оцениваются обоснованность замечаний, ложные срабатывания и стоимость. Независимость модели не гарантирует качества рецензии; второй агент подключается, только если даёт измеримую пользу.
