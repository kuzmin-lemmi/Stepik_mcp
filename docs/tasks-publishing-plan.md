# План: публикация тестов и задач на программирование

_Создан 2026-11-02. Продолжение [этапа 3а](ROADMAP.md#этап-3-безопасная-публикация): текстовые шаги и картинки уже публикуются и проверены на курсе `241862`._

**Цель:** ИИ создаёт и правит в локальном уроке тесты и задачи на код, а сервер публикует их на Stepik так же безопасно, как текст: план → diff → подтверждение → apply.

**Итоговый критерий:** на курсах `266999`, `276752` и `241862` каждый тест и каждая задача проходят проверку «скачать → собрать обратно» без единого изменённого поля. На тестовом курсе через чат пройден цикл «создать → изменить → откатить» для каждого поддержанного типа.

---

## Главная идея

Сейчас `.md` хранит задачу с потерями: в нём нет checker-кода, части тестов, лимитов, header и footer, настроек теста. Публиковать задачу из такого файла нельзя.

Поэтому в задаче будут жить **две вещи**:

1. **Исходник Stepik**: `.stepik/steps/<step_id>.json`, ровно то, что вернул API при скачивании. Его никто не правит.
2. **Редактируемая часть**: YAML-блок в `.md` с полями, которые автор действительно меняет.

При публикации сервер берёт исходник, **накладывает на него только изменённые поля YAML** и отправляет результат. Всё, чего нет в YAML (неизвестные поля, служебные настройки, `templates_data`), уходит на Stepik без изменений.

```text
скачивание:  Stepik ──► .stepik/steps/<id>.json   (база, не правится)
                    └─► урок.md: условие + YAML   (правит автор или ИИ)

публикация:  база + изменённые поля YAML ──► проверка ──► diff ──► PUT/POST
```

Тот же исходник служит базой для трёхстороннего сравнения: сервер видит, что поменял автор, а что изменилось на Stepik после скачивания.

## Как задача будет выглядеть в `.md`

Тест (поля взяты из реального шага `7449630` курса `241862`):

````markdown
<!-- step_id: 7449630 -->
## Шаг 3 | step_id: 7449630 | choice

Что такое программа?

```yaml stepik
type: choice
multiple: false          # source.is_multiple_choice
shuffle: true            # !source.preserve_order
show: 4                  # source.sample_size
options:
  - text: создание сложных математических формул
  - text: работа только с числами и данными
  - text: последовательность инструкций для компьютера
    correct: true
feedback_correct: ""
feedback_wrong: ""
```
````

Задача на код (шаг `7451961`):

````markdown
```yaml stepik
type: code
languages: [julia]
limits: {time: 5, memory: 256}          # execution_time_limit, execution_memory_limit
templates:
  julia: {header: "", code: "", footer: ""}
samples: []                              # открытые примеры
tests:                                   # source.test_cases
  - {input: "\n", output: "50\n"}
checker: checkers/7451961.py             # source.code лежит отдельным файлом
```
````

- Большие наборы тестов хранятся файлами `tests/<step_id>/01.in`, `01.out`, а в YAML пишется `tests: tests/7451961/`.
- Новая задача создаётся тем же блоком под меткой `<!-- new_step -->`. Базы у неё нет, поэтому недостающие поля сервер заполняет значениями Stepik по умолчанию и показывает их в плане.

## Этапы

Каждый этап заканчивается тестами без сети и проверяемым критерием. Этапы 1–2 ничего не пишут на Stepik.

### Этап 0. Подготовка

- [ ] Исправить разбор `<li><p>…</p></li>` в `render.py`: сейчас такой пункт превращается в пустой `- `. Предупреждение о потерях в плане должно ловить и этот случай.
- [ ] Разделить `publish.py` на общую часть (план, проверки, снимок, журнал) и **адаптеры типов**: `text`, `choice`, `code` и так далее. У каждого адаптера три функции: `to_yaml(source)`, `apply_yaml(source, yaml)`, `validate(block)`.
- [ ] Добавить зависимость для YAML (`pyyaml`) или выбрать JSON-подобный формат без зависимостей. Решить до этапа 1.

**Критерий:** текстовая публикация работает как раньше, все существующие тесты проходят.

### Этап 1. Исходник без потерь при скачивании

- [ ] `stepik_cache_lesson` и `stepik_cache_course_text_lessons` сохраняют `.stepik/steps/<step_id>.json` для каждого шага. Запись атомарная, существующие файлы не перезаписываются.
- [ ] Для уже скачанных уроков: инструмент `stepik_fetch_step_sources(course_id, lesson_position)` докачивает только исходники и не трогает `.md`. В плане такой исходник помечается как «база взята сейчас, а не при скачивании».
- [ ] Из исходника убираются статистика и служебные поля (`viewed_by`, `passed_by`, `correct_ratio`, `progress`, `subscriptions`, `discussion_*`), чтобы файл менялся только при изменении задачи.
- [ ] Отдельно скачивать архив тестов задачи на код (`/api/step-sources/<id>/tests`), если в `test_cases` попадают не все тесты.

**Критерий:** для всех шагов курсов `266999`, `276752` и `241862` исходник сохранён, а повторное скачивание даёт тот же файл.

### Этап 2. YAML и проверка «собрать обратно»

- [ ] Адаптеры `choice`, `string`, `number`, `matching`, `sorting`, `code`: исходник → YAML и YAML + исходник → блок.
- [ ] Новые уроки скачиваются сразу с YAML-блоками. Старые `.md` не переписываются. Для них `stepik_cache_lesson` сможет сохранить свежую копию в отдельный файл `…lesson-<id>.v2.md`, а автор сам решит, на какой перейти.
- [ ] Команда проверки (скрипт или тест на сохранённых исходниках): для каждого шага `apply_yaml(база, to_yaml(база)) == база`. Каждое расхождение записывается и покрывается тестом.
- [ ] Неизвестный тип шага получает YAML только с `type` и не публикуется, но и не теряется.

**Критерий:** 100% тестов и задач трёх курсов проходят проверку без изменённых полей.

### Этап 3. Публикация тестов и простых задач

Типы `choice`, `string`, `number`, `matching`, `sorting`.

- [ ] План показывает diff по полям: «вариант 3: правильный → неправильный», «добавлен вариант 5», «показывать вариантов: 4 → 5».
- [ ] Проверки до отправки:
  - в тесте с одним ответом ровно один правильный вариант, с несколькими ответами хотя бы один;
  - `show` не больше числа вариантов;
  - у `number` ответ — число, у `string` ответ не пустой;
  - у `matching` пары не повторяются.
- [ ] **Защита учеников.** Если шаг уже решали (`passed_by > 0`), план предупреждает: смена правильного ответа затронет тех, кто решил. Применение требует явного согласия автора именно на этот шаг.
- [ ] Исследование на `241862`: принимает ли Stepik `PUT` с изменёнными вариантами; что происходит с прошлыми попытками учеников; сохраняются ли `cost` и `max_submissions_count`. Результаты записать в [design-notes](design-notes.md).

**Критерий:** на `241862` созданы и изменены тест с одним ответом, тест с несколькими ответами, `string`, `number` и `matching`. Повторный план после каждой публикации отвечает «отправлять нечего».

### Этап 4. Задачи на программирование

- [ ] Адаптер `code`: языки, лимиты, шаблоны (header, code, footer), открытые примеры, тесты, checker отдельным файлом.
- [ ] Выяснить на `241862`, какое поле Stepik считает главным для шаблонов при записи: `options.code_templates` или `source.templates_data` (формат `::julia`, `::header`, `::code`, `::footer`). Собирать именно его.
- [ ] Тесты: из YAML и из папки `tests/<step_id>/`. Если тестов больше, чем помещается в `test_cases`, разобраться с архивом тестов.
- [ ] **Локальная проверка до публикации (по желанию автора).** Если рядом лежит эталонное решение `solutions/<step_id>.<ext>` и на компьютере есть нужный язык, сервер прогоняет его на всех тестах. Если хоть один тест падает, план не строится. Эталонное решение на Stepik не отправляется.
- [ ] Проверки: хотя бы один тест; у каждого языка есть шаблон; лимиты в допустимых пределах Stepik; checker-файл существует и лежит внутри папки курса.

**Критерий:** на `241862` создана задача на Julia с тестами и шаблоном, затем изменены тесты и лимиты. Решение, отправленное в интерфейсе Stepik, проходит проверку.

### Этап 5. Откат

Задачи рискованнее текста, поэтому откат нужен до первой записи в боевой курс.

- [ ] `stepik_rollback_lesson(course_id, lesson_position, snapshot)`: показывает diff между Stepik и снимком и восстанавливает шаги из снимка через тот же план и применение.
- [ ] Созданные шаги в первой версии не удаляются. План отката их перечисляет, удалить их можно вручную.

**Критерий:** на `241862` любой шаг после публикации возвращается к состоянию из снимка.

## Открытые вопросы к API Stepik

Вопросы решаются экспериментами на `241862`, ответы записываются в [design-notes](design-notes.md).

1. Пересчитывает ли Stepik прошлые попытки учеников при смене правильного ответа или тестов?
2. Нужно ли при `PUT` отправлять статистику и служебные поля или достаточно `block`, `position`, `cost` и ограничений попыток? При текстовой публикации отправлялся полный объект, и это сработало.
3. Как устроен архив тестов задачи на код и как его загружать?
4. Есть ли у `choice` ограничения на HTML в вариантах (`is_html_enabled`)?
5. Как публиковать шаги с вариациями (`variations_count > 1`)? В первой версии такие шаги лучше пропускать.

## Что не входит в план

- удаление шагов и уроков;
- задачи типов `dataset`, `table`, `fill-blanks`, `admin`, SQL и другие редкие: они сохраняются без потерь, но не публикуются;
- внешний грейдер для языков, которых нет в Stepik (этап 7 дорожной карты).
