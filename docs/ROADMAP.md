# Дорожная карта

_Обновлено: 2026-09-23. Порядок согласован с автором проекта._

**Цель:** скачивать курс со Stepik целиком, писать и улучшать уроки вместе с ИИ и выкладывать их обратно безопасно, с diff и подтверждением. Работать нужно одинаково в **Claude** (Code и Desktop) и в **OpenCode**.

Что строим и зачем, описано в [PRD](PRD.md). Здесь только порядок работ, их состояние и критерии готовности.

## Принципы порядка

1. **Запись на Stepik появляется только после формата хранения без потерь.** Если урок нельзя скачать и собрать обратно без изменений, то публиковать его отредактированную версию нельзя.
2. **Первая запись идёт только в тестовый курс.** Боевые курсы попадают в список разрешённых для записи только после проверки на тестовом.
3. **Этап закрывается проверяемым критерием,** а не ощущением «вроде работает».
4. **Редакторский процесс (этап 4) можно вести параллельно с этапами 1–3:** ему не нужна запись на Stepik.

## Текущее состояние

### Реализовано и проверено

| Возможность | Основание и границы проверки |
| --- | --- |
| Локальный MCP через stdio | Авторизация и чтение проверены реальными запросами в OpenCode. Регистрация 16 инструментов проверяется в CI |
| Структура курса, уроки и отдельные шаги | Работают инструменты чтения. Markdown передаёт учебный материал, но **не является** полной копией настроек и медиа Stepik |
| `stepik_cache_lesson` | Создаёт папки курса и всех модулей и сохраняет выбранный урок в `.md`. Существующий файл не перезаписывается; повторное получение идёт без запросов к API |
| `stepik_step_comments`, `stepik_lesson_comments` | Основные обсуждения и ответы через discussion proxy, без вкладки решений. Проверены на реальном уроке и тестами |
| `stepik_cache_lesson_comments` | Сохраняет `.comments.md` рядом с уже сохранённым уроком, урок не меняет |
| `stepik_cache_course_text_lessons` | Сохраняет все уроки курса, но только шаги типа `text`. Проверен на курсе `276752` |
| `stepik_lesson_stats` | Проверены источник полей, обработка пустых значений и перевод секунд в минуты. С интерфейсом преподавателя значения ещё не сверены |

### Код есть, достоверность не подтверждена

| Инструмент | Что проверить |
| --- | --- |
| `stepik_step_stats` | Фильтрацию попыток, полноту выборки, знаменатель успешности |
| Оценки и реакции шагов | Какие endpoint реально существуют и что значат их поля |
| `stepik_wrong_submissions` | Отбор неверных решений и обезличивание: исключение полей не обезличивает сам текст решения |
| `stepik_course_reviews` | Полноту и привязку отзывов к курсу |
| `stepik_lesson_bundle` | Весь сценарий целиком; наследует ограничения входящих инструментов |

Эти инструменты вызываются только по явному запросу. То, что инструмент зарегистрирован, ещё не значит, что его данные достоверны.

### Главные ограничения сейчас

- **Урок нельзя загрузить обратно.** HTML превращается в Markdown с потерями, а у задач сохраняется только часть настроек. Это решает этап 2.
- Структура курса в `.course.json` является снимком и сама не обновляется.
- Путь по умолчанию `C:\Courses` работает только в Windows. На Linux и macOS нужно задать `COURSE_WORKSPACE_ROOT`.

## Этап 2. Полная загрузка без потерь

Самый важный этап: без него публикация невозможна.

- [ ] **Формат хранения.** Урок хранится как читаемый `.md`, а рядом лежит исходная версия каждого шага в формате Stepik (`.stepik/step-<id>.json`) как база для сравнения.
  - Текстовые шаги редактируются в Markdown и собираются обратно в HTML.
  - У тестов и задач на код настройки задаются явно (YAML-блок): варианты, ответы, шаблоны, тесты, лимиты, checker.
  - Неизвестный тип шага сохраняется как есть и не теряется.
- [ ] `stepik_pull_course`: все уроки и все типы шагов, метаданные курса (описание, цели, требования, авторы, обложка), по желанию изображения.
- [ ] `stepik_refresh_lesson` и `stepik_refresh_structure`: сравнение трёх версий (база на момент скачивания, локальная, текущая на Stepik). Локальные правки не перезаписываются, при конфликте сохраняется отдельный снимок.
- [ ] Привязка локального черновика к `lesson_id` после публикации.
- [ ] **Проверка без потерь:** скачать урок и собрать обратно, результат должен совпасть с тем, что на Stepik, для всех шагов реальных курсов.

**Критерий:** на курсах `266999` и `276752` совпадают 100% шагов, а каждое расхождение объяснено и покрыто тестом.

## Этап 3. Безопасная публикация

- [ ] **Исследование API на тестовом курсе:** запись `step-sources`, `lessons`, `units`, `sections`, порядок создания и привязки, ограничения. Результаты записать в [design-notes](design-notes.md).
- [ ] Список `ALLOWED_WRITE_COURSES` в настройках сервера. По умолчанию он пуст, и писать никуда нельзя. Разрешение не хранится в файлах курса, потому что агент может их редактировать.
- [ ] `stepik_plan_push(lesson)`: diff по ID шагов (изменён, новый, удалён, перемещён), ничего не отправляет и возвращает `plan_id`.
- [ ] `stepik_apply_push(plan_id)`: перед отправкой проверяет, что на Stepik урок не менялся с момента плана, снимает снимок, отправляет изменения и пишет журнал.
- [ ] `stepik_create_lesson` из черновика: создать урок, привязать к модулю, записать новые ID в файл и `.course.json`.
- [ ] `stepik_rollback_lesson`: показывает diff и восстанавливает снимок через тот же plan/apply.
- [ ] Журнал записи `logs/stepik-write.log`: время, курс, урок, шаг, операция, хеши до и после, результат. Секреты в журнал не пишутся.
- [ ] Удаление шагов и уроков в первой версии не реализуется.

**Критерий:** в тестовом курсе через чат проходит полный цикл «создать урок → изменить → выложить → откатить», а журнал и снимки позволяют восстановить любое состояние.

## Этап 4. Редакторский процесс

Бывшие пункты 2–9 прежнего плана. Этап можно вести параллельно с этапами 1–3.

- [ ] Файлы папки курса: `COURSE_STATE.md`, `DECISIONS.md`, `COURSE_STYLE.md`, `rules/` (`WRITING_RULES`, `LESSON_STRUCTURE`, `TASK_RULES`, `CODE_RULES`, `REVIEW_RULES`), `sessions/HANDOFF_TEMPLATE.md`. Уроки не перемещать, сгенерированные файлы не править.
- [ ] Собрать правила автора из материалов и переписки. Предложения модели отделить от принятых правил; принятые правила подтверждает автор.
- [ ] Правила выбора контекста: читать текущий урок и нужные правила; другие уроки только по конкретным зависимостям; комментарии и аналитику только по запросу.
- [ ] Skill **REVIEW**: отчёт в `sessions/` без изменения урока. Для каждого замечания указать место, проблему, основание, последствия для ученика, предлагаемую правку и степень уверенности. Первая проверка на уроке 5.2 курса `266999`.
- [ ] Skill **REVISE**: правки по согласованным замечаниям с сохранением ID шагов и повторной проверкой.
- [ ] **Handoff**: продолжение работы в новой сессии без старой переписки.
- [ ] Skill **CREATE**: новый урок продолжает курс без повторов и скрытых требований к знаниям ученика.
- [ ] Skill **PUBLISH** (после этапа 3): подготовка плана, показ diff, публикация после подтверждения.
- [ ] Формат skills (`SKILL.md`) проверить и в Claude Code, и в OpenCode.

**Критерий:** на одном уроке пройден цикл REVIEW → согласование → REVISE → повторная проверка → handoff, а автор оценил замечания как полезные.
