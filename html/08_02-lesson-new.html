Урок 8.2. Разбор ответа: JSON снова в деле

Аннотация:
В уроке 8.1 ПривычкаБот научился спрашивать погоду: aiohttp, params=, await response.json(). Ответ пришёл — словарь в три уровня, где нужные боту два числа спрятаны внутри. Сегодня достанем их оттуда и превратим в строку для утреннего сообщения: «+3, ясно».

Главная трудность не в том, чтобы достать число. Ответ пишет чужая программа, и он не всегда такой, как мы ждём. Город может не найтись, а формат — поменяться. Бот должен это пережить.

🔁 1. JSON вернулся

В уроке 7.1 JSON ушёл из ПривычкаБота: хранить данные в файле оказалось неудобно, и их забрала база. Но сам формат никуда не делся. В уроке 8.1 сервер прислал ответ — и это был JSON.

Только теперь у JSON другая роль. Раньше это было хранилище: бот записывал файл и сам же его читал. Теперь это формат обмена: одна программа пишет, другая читает. Так договариваются программы в интернете: ответы почти всех сервисов — JSON.

Куда же делся json.loads()? В уроке 8.1 мы вызывали await response.json() и сразу получали словарь. Проверим, что внутри. Создайте в http_lab файл bridge_demo.py:

import asyncio
import json

import aiohttp

URL = "https://api.open-meteo.com/v1/forecast"
PARAMS = {
    "latitude": 55.79,
    "longitude": 49.12,
    "current": "temperature_2m,weather_code",
}


async def main() -> None:
    async with aiohttp.ClientSession() as session:
        async with session.get(URL, params=PARAMS) as response:
            text = await response.text()
            data = await response.json()

    print(type(text).__name__, text[:45])
    print(type(data).__name__, data["current"])
    print(json.loads(text) == data)


asyncio.run(main())

Здесь у одного ответа два вызова. response.text() отдаёт тело ответа как есть — строкой. response.json() отдаёт его же, но уже словарём. Последняя строка разбирает строку сама, через json.loads() из урока 2.5, и сравнивает с тем, что дала библиотека.

Запустите python bridge_demo.py:

str {"latitude":55.79072,"longitude":49.10105,"ge
dict {'time': '2026-11-01T14:15', 'interval': 900, 'temperature_2m': 3.1, 'weather_code': 0}
True

Первая строка: сервер прислал str — текст, который начинается с фигурной скобки. Вторая: json() вернул dict. Третья: True — словарь из json.loads(text) равен словарю из response.json().

урок 2.5:   файл    →  json.load(f)        →  словарь
урок 8.2:   ответ   →  response.json()     →  словарь
                      (внутри — json.loads)

Разбирать JSON вручную не нужно: это делает библиотека. А вот что делать со словарём дальше — решаем мы.

🔑 response.json() — это json.loads() за вас:
Сервер присылает текст в формате JSON. aiohttp дочитывает его и разбирает в словарь той же функцией, что вы вызывали в уроке 2.5.

🔭 2. Два ответа целиком

Боту понадобятся два запроса к Open-Meteo:

  • Геокодер: отправляем название города — получаем координаты.
  • Прогноз: отправляем координаты — получаем погоду.

Пользователь напишет «Казань», а прогнозу нужны широта и долгота. Поэтому сначала геокодер, потом прогноз. Прежде чем доставать из ответов значения, посмотрим на них целиком.

Словарь из ответа можно вывести через print(), но он уйдёт в одну длинную строку, как в уроке 8.1. Для отладки в уроке 2.5 был способ получше — json.dumps() с отступами:

json.dumps(data, indent=2, ensure_ascii=False)

indent=2 переносит каждый ключ на свою строку и сдвигает вложенное на два пробела. ensure_ascii=False оставляет кириллицу кириллицей, а не К....

Создайте look_demo.py:

import asyncio
import json

import aiohttp

GEO_URL = "https://geocoding-api.open-meteo.com/v1/search"
FORECAST_URL = "https://api.open-meteo.com/v1/forecast"
GEO_PARAMS = {"name": "Казань", "count": 1, "language": "ru"}
FORECAST_PARAMS = {
    "latitude": 55.78874,
    "longitude": 49.12214,
    "current": "temperature_2m,weather_code",
}


async def get_json(url: str, params: dict) -> dict:
    async with aiohttp.ClientSession() as session:
        async with session.get(url, params=params) as response:
            return await response.json()


async def main() -> None:
    geo = await get_json(GEO_URL, GEO_PARAMS)
    print(json.dumps(geo, indent=2, ensure_ascii=False))

    forecast = await get_json(FORECAST_URL, FORECAST_PARAMS)
    print(json.dumps(forecast, indent=2, ensure_ascii=False))


asyncio.run(main())

Запрос вынесен в функцию get_json(): открыть сессию, отправить запрос, вернуть словарь. Это три строки из урока 8.1, только адрес и параметры приходят аргументами. Координаты Казани в FORECAST_PARAMS — те, что вернёт геокодер. Пока мы переписали их руками, в разделе 7 код возьмёт их сам.

Чужой ответ печатаем через json.dumps(data, indent=2, ensure_ascii=False). Отступы показывают вложенность: где словарь, где список и на какой глубине лежит нужное значение.

🪜 3. Путь к значению

Значение внутри вложенного словаря достают по шагам: каждый шаг — одна пара квадратных скобок. Для температуры путь такой:

forecast                                →  словарь ответа
forecast["current"]                     →  вложенный словарь current
forecast["current"]["temperature_2m"]   →  число 3.0

Читается слева направо. forecast["current"] возвращает вложенный словарь. От него ["temperature_2m"] возвращает число. Каждые скобки работают с тем, что вернули предыдущие.

В ответе геокодера на пути есть список. У списка нет ключей, только номера, поэтому шаг к первому месту — [0]:

geo["results"]                  →  список мест
geo["results"][0]               →  словарь: первое место
geo["results"][0]["latitude"]   →  число 55.78874

Пройдём оба пути по шагам и на каждом посмотрим, что получили. Скопируйте look_demo.py в path_demo.py и замените функцию main():

async def main() -> None:
    geo = await get_json(GEO_URL, GEO_PARAMS)
    results = geo["results"]
    print("results:", type(results).__name__, "из", len(results))
    place = results[0]
    print("place:", type(place).__name__)
    print("координаты:", place["latitude"], place["longitude"])

    forecast = await get_json(FORECAST_URL, FORECAST_PARAMS)
    current = forecast["current"]
    print("температура:", current["temperature_2m"])
    print("код погоды:", current["weather_code"])

Запустите python path_demo.py:

results: list из 1
place: dict
координаты: 55.78874 49.12214
температура: 3.0
код погоды: 0

Каждая строка подтверждает схему из раздела 2. results — список из одного элемента, place — словарь, в нём координаты. current — словарь, в нём два нужных боту значения.

Промежуточные переменные results, place, current — для наглядности. Путь можно записать и одной строкой: geo["results"][0]["latitude"]. Результат тот же.

🔑 Путь — ключ за ключом:
Каждые скобки делают один шаг вглубь: ключ — для словаря, номер — для списка. Чтобы записать путь, смотрим на ответ и называем шаги сверху вниз.

💥 4. Города нет — бот падает

Путь из раздела 3 сработал, потому что Казань нашлась. Пользователь же может написать что угодно: опечатку, выдуманное название, город, которого нет в базе сервиса. Проверим, что тогда пришлёт геокодер.

Скопируйте look_demo.py в crash_demo.py и замените main():

🛡 5. Читаем безопасно

Ключа может не быть — значит, нужен способ спросить словарь «есть ли у тебя такой ключ» и не упасть. Он знаком вам с урока 2.3: метод .get().

Шаг 1. .get() вместо скобок

Возьмём ответ геокодера на «Привычкоград» и сравним способы. Создайте get_demo.py, в интернет он не ходит:

data = {"generationtime_ms": 0.19586086}

print(data.get("results"))
print(data.get("results", []))
print(not None, not [], not [{"name": "Казань"}])
print(data["results"])

Запустите python get_demo.py:

None
[]
True True False
Traceback (most recent call last):
  File "get_demo.py", line 6, in <module>
    print(data["results"])
          ~~~~^^^^^^^^^^^
KeyError: 'results'

Разберём строки по очереди.

  • data.get("results") — ключа нет, вернулось None. Не ошибка, а ответ «ничего».
  • data.get("results", []) — второй аргумент задаёт, что вернуть вместо None. Здесь — пустой список.
  • not None и not [] — оба True. Список с одним местом даёт False. Одна проверка if not results ловит и отсутствующий ключ, и пустой список.
  • data["results"] — та же ошибка, что в разделе 4.

Шаг 2. Функция parse_city()

Теперь соберём разбор ответа геокодера в функцию. Она получает словарь ответа и возвращает координаты — или None, если их нет. Так же устроены проверки из урока 6.3: parse_frequency() и parse_time() возвращали значение или None, а плохие случаи отсекались ранним return из урока 2.4.

Создайте в http_lab файл weather_parse.py:

"""Разбор ответов Open-Meteo."""


def parse_city(data: dict) -> tuple[float, float] | None:
    results = data.get("results")
    if not results:
        return None

    place = results[0]
    latitude = place.get("latitude")
    longitude = place.get("longitude")
    if latitude is None or longitude is None:
        return None
    return latitude, longitude

Читаем сверху вниз.

results = data.get("results")        →  список мест или None
if not results: return None          →  ключа нет или список пуст
place = results[0]                   →  первое место: список точно не пуст
latitude = place.get("latitude")     →  число или None
if ... is None: return None          →  координат нет
return latitude, longitude           →  кортеж из двух чисел

Почему в последней проверке is None, а не not latitude? Широта 0 — это экватор, настоящая координата. not 0 — True, и город на экваторе функция бы потеряла. is None отсекает только отсутствие значения.

results[0] здесь записан скобками, и это безопасно: строкой выше мы проверили, что список не пуст.

Шаг 3. Проверка

Создайте safe_demo.py. Он берёт parse_city() из weather_parse.py и пробует три настоящих запроса и два ответа, собранных руками:

import asyncio

import aiohttp

from weather_parse import parse_city

GEO_URL = "https://geocoding-api.open-meteo.com/v1/search"


async def get_json(url: str, params: dict) -> dict:
    async with aiohttp.ClientSession() as session:
        async with session.get(url, params=params) as response:
            return await response.json()


async def main() -> None:
    for city in ["Казань", "Москва", "Привычкоград"]:
        params = {"name": city, "count": 1, "language": "ru"}
        geo = await get_json(GEO_URL, params)
        print(city, "->", parse_city(geo))

    print("пустой список ->", parse_city({"results": []}))
    print("без координат ->", parse_city({"results": [{"name": "Казань"}]}))


asyncio.run(main())

Запустите python safe_demo.py:

Москва -> (55.75204, 37.61781)
Привычкоград -> None
пустой список -> None
без координат -> None

Для Казани и Москвы — кортеж координат. Для «Привычкограда», пустого списка и места без координат — None. Программа ни разу не упала. Что ответить пользователю, если пришёл None, решит тот, кто функцию вызвал, — в разделе 7.

🔑 Чужой ответ читаем через .get():
.get() возвращает None, если ключа нет. Функция разбора проверяет каждый шаг пути и при первом пропуске возвращает None. Скобки допустимы только там, где строкой выше проверено, что значение есть.

🌤 6. Код погоды → слово

Из ответа прогноза боту нужны температура и код погоды. Температура — число, его можно показать. А "weather_code": 0 пользователю ничего не скажет. Нужно слово.

Шаг 1. Словарь кодов

Коды погоды — общая таблица метеорологов, WMO. В ней число означает состояние неба: 0 — ясно, 3 — пасмурно, 61 — слабый дождь. Open-Meteo присылает код из этой таблицы, а перевести его в слово — наша работа.

Число → слово — это словарь. Добавьте его в weather_parse.py сразу после строки документации, перед parse_city():

WEATHER_CODES = {
    0: "ясно",
    1: "в основном ясно",
    2: "переменная облачность",
    3: "пасмурно",
    45: "туман",
    48: "туман с изморозью",
    51: "слабая морось",
    53: "морось",
    55: "сильная морось",
    61: "слабый дождь",
    63: "дождь",
    65: "сильный дождь",
    71: "слабый снег",
    73: "снег",
    75: "сильный снег",
    80: "ливень",
    95: "гроза",
}

Ключи — числа, без кавычек: в ответе код приходит числом, "weather_code": 0. Строка "0" ключом 0 не считается, и такой словарь ничего бы не нашёл.

В словаре не все коды таблицы, а самые частые. Каких нет — например, 77, снежные зёрна. Если сервис пришлёт такой код, WEATHER_CODES[77] упадёт с KeyError. Значит, и здесь нужен .get() — с запасным текстом вторым аргументом.

Шаг 2. Знак у температуры

В утреннем сообщении температура должна выглядеть так, как её пишут в прогнозах: целое число со знаком, «+3» или «-3». Целое даёт round(). Знак даёт формат внутри f-строки — вы встречали формат {hours:02d} в parse_time() урока 6.3. Здесь другой: {degrees:+d} — целое число, и знак ставить всегда, даже плюс.

Проверим и словарь, и знак. Создайте codes_demo.py:

from weather_parse import WEATHER_CODES

for code in [0, 51, 77]:
    print(code, "->", WEATHER_CODES.get(code, "без описания"))

for temperature in [17.6, 3.0, -3.0, -0.4]:
    degrees = round(temperature)
    print(temperature, "->", degrees, f"{degrees:+d}")

Запустите python codes_demo.py:

0 -> ясно
51 -> слабая морось
77 -> без описания
17.6 -> 18 +18
3.0 -> 3 +3
-3.0 -> -3 -3
-0.4 -> 0 +0

Коды: известные превратились в слова, неизвестный 77 — в запасной текст, и программа не упала.

Температура: 17.6 округлилась до 18, а формат добавил плюс. У -3 минус свой. А вот последняя строка: -0.4 округлилось до 0, и формат честно написал +0. В прогнозах так не пишут — ноль пишут без знака. Этот случай придётся обработать отдельно.

Что должна вернуть функция

Теперь у нас есть всё, чтобы из ответа прогноза получить строку для бота:

{"current": {"temperature_2m": 3.0, "weather_code": 0}}   →  "+3, ясно"
{"current": {"temperature_2m": -0.4, "weather_code": 3}}  →  "0, пасмурно"
{"generationtime_ms": 0.2}                                →  None

Эту функцию, describe_weather(), вы напишете в задаче 1. Она встанет в weather_parse.py рядом с parse_city(), а в практикуме 8.4 вместе с ней перейдёт в проект без изменений.

🔑 Перевод кода — словарём и .get():
WEATHER_CODES.get(code, "без описания") находит слово для известного кода и не падает на неизвестном. Знак температуры ставит формат {degrees:+d}, кроме нуля.

✍️ Задача 1. Погода одной строкой

Уровень: ⭐⭐ Basic

Это та часть утреннего сообщения, которую бот покажет пользователю. Функция, которую вы напишете, в разделе 7 разберёт настоящий ответ Open-Meteo, а в практикуме 8.4 войдёт в код ПривычкаБота без изменений.

Напишите функцию describe_weather(data), которая получает словарь ответа прогноза и возвращает погоду строкой: "+3, ясно". Словарь WEATHER_CODES уже есть в шаблоне.

Важно: нужно написать только функцию. Не используйте input() и print() внутри решения.

✅ Что должна делать функция

  • Взять из data вложенный словарь по ключу "current". Если его нет или он пуст — вернуть None
  • Взять из него "temperature_2m" и "weather_code". Если нет хотя бы одного — вернуть None

  • Найти слово для кода в WEATHER_CODES. Если кода там нет — взять "без описания"
  • Вернуть строку "температура, слово": через запятую и пробел

🧩 7. Город → координаты → погода

Добавьте в конец weather_parse.py свою describe_weather() из задачи 1. Теперь в файле три части: словарь кодов и две функции разбора.

Показать weather_parse.py целиком

def parse_city(data: dict) -> tuple[float, float] | None:
    results = data.get("results")
    if not results:
        return None

    place = results[0]
    latitude = place.get("latitude")
    longitude = place.get("longitude")
    if latitude is None or longitude is None:
        return None
    return latitude, longitude


def describe_weather(data: dict) -> str | None:
    current = data.get("current")
    if not current:
        return None

    temperature = current.get("temperature_2m")
    code = current.get("weather_code")
    if temperature is None or code is None:
        return None

    degrees = round(temperature)
    if degrees == 0:
        sign = "0"
    else:
        sign = f"{degrees:+d}"
    text = WEATHER_CODES.get(code, "без описания")
    return f"{sign}, {text}"

Осталось связать два запроса. Название города → геокодер → parse_city() → координаты → прогноз → describe_weather() → строка. И на каждом шаге, где может прийти None, решить, что сказать пользователю.

Создайте full_demo.py:

import asyncio

import aiohttp

from weather_parse import describe_weather, parse_city

GEO_URL = "https://geocoding-api.open-meteo.com/v1/search"
FORECAST_URL = "https://api.open-meteo.com/v1/forecast"


async def get_json(url: str, params: dict) -> dict:
    async with aiohttp.ClientSession() as session:
        async with session.get(url, params=params) as response:
            return await response.json()


async def weather_for(city: str) -> str:
    geo = await get_json(GEO_URL, {"name": city, "count": 1, "language": "ru"})
    coords = parse_city(geo)
    if coords is None:
        return f"{city}: город не найден"

    latitude, longitude = coords
    params = {
        "latitude": latitude,
        "longitude": longitude,
        "current": "temperature_2m,weather_code",
    }
    forecast = await get_json(FORECAST_URL, params)
    weather = describe_weather(forecast)
    if weather is None:
        return f"{city}: погода недоступна"
    return f"{city}: {weather}"


async def main() -> None:
    for city in ["Казань", "Москва", "Привычкоград"]:
        print(await weather_for(city))


asyncio.run(main())

Посмотрите на weather_for(). Это тот код, который в практикуме 8.4 окажется в хэндлере. В нём две проверки на None, и обе заканчиваются понятным ответом:

  • parse_city() вернула None — города нет, так и говорим.
  • describe_weather() вернула None — ответ прогноза не такой, как мы ждали. Говорим, что погода недоступна.

Функции разбора ничего не знают о пользователе: они только отвечают «вот значение» или «его нет». Что сказать человеку, решает вызывающий код. Это разделение из урока 2.4: функция возвращает, а не печатает.

Запустите python full_demo.py:

Казань: +3, ясно
Москва: +3, в основном ясно
Привычкоград: город не найден

Две настоящие погоды и одно честное «город не найден» вместо KeyError. Москва: 2.9 округлилось до +3, код 1 стал «в основном ясно».

🔑 Функция разбора отвечает «есть» или «нет», ответ пользователю выбирает вызывающий:
parse_city() и describe_weather() возвращают значение или None. Каждое None вызывающий код превращает в понятное сообщение.

🤝 8. Почему не доверяем ответу

Может показаться, что все эти .get() и проверки — ради одного случая: города нет. Но защищаемся мы от большего.

Ответ пишет чужая программа. Open-Meteo — не наш код: его авторы могут переименовать ключ, убрать поле, поменять вложенность. Документацию они обновят, а наш бот об этом не узнает.

Представим, что так случилось: в новой версии сервиса "temperature_2m" стал называться "temperature". Создайте changed_demo.py:

from weather_parse import describe_weather

changed = {
    "current": {"time": "2026-11-01T14:45", "temperature": 3.0, "weather_code": 0}
}

print(describe_weather(changed))
print(changed["current"]["temperature_2m"])

Первая строка разбирает изменённый ответ нашей функцией, вторая — путём со скобками, как в разделе 3. Запустите python changed_demo.py:

None
Traceback (most recent call last):
  File "changed_demo.py", line 8, in <module>
    print(changed["current"]["temperature_2m"])
          ~~~~~~~~~~~~~~~~~~^^^^^^^^^^^^^^^^^^
KeyError: 'temperature_2m'

describe_weather() вернула None, и в full_demo.py пользователь увидел бы «погода недоступна». Путь со скобками упал. В боте такое падение означает: хэндлер не ответил, и утреннее сообщение не пришло совсем — ни погоды, ни привычек.

С этой мыслью вы уже встречались. В уроке 5.2 было правило «кнопка живёт дольше кода»: сообщение с клавиатурой остаётся в чате, а бот за это время меняется. Обработчик должен пережить нажатие на старую кнопку.

Здесь то же самое, только с другой стороны. Там наш код менялся, а данные в чате оставались старыми. Здесь наш код прежний, а меняются данные, которые приходят снаружи. В обоих случаях бот не управляет тем, что получает, и должен пережить неожиданное.

урок 5.2:  данные старые, код новый      →  обработчик переживает старую кнопку
урок 8.2:  код прежний, данные новые     →  разбор переживает другой ответ

Худшее, что может случиться с погодой, — она не покажется. Утреннее сообщение с привычками должно прийти всё равно. Поэтому разбор ответа не падает, а возвращает None, и бот продолжает работу.

🔑 Чужим данным не доверяем:
Формат ответа определяет не наш код, а чужой сервис, и он может измениться. Разбор проверяет каждый шаг пути: что-то не так — None, а не падение бота.
