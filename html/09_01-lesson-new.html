⏰ 1. Кто напишет в 07:30?

Вспомните, как работает каждый хэндлер ПривычкаБота. Аня отправила /today — хэндлер ответил. Нажала кнопку — хэндлер изменил сообщение. Всё, что делает бот, — ответ на чьё-то действие. Хэндлер вызывается, когда приходит обновление от Telegram, и только тогда.

В 07:30 Аня спит. Обновлений нет, и ни один хэндлер не вызовется. Чтобы сообщение пришло, у бота должна быть ещё одна работа, не связанная с обновлениями: следить за часами.

хэндлеры        ждут обновлений от Telegram  →  отвечают
новая работа    следит за часами             →  пишет сама, когда пора

Обе работы должны идти одновременно: пока бот ждёт 07:30, он продолжает отвечать на /today. Модуль 3 научил нас именно этому — нескольким корутинам в одном event loop.

Что бот будет присылать

  • Утреннее сообщение — в 07:30, каждому, у кого есть привычки. Текст собирает build_morning_text() из урока 8.4 без изменений.
  • Напоминание о привычке — в её remind_time: «⏰ Пора: Растяжка» и кнопка отметки. Если привычка уже отмечена сегодня, напоминать не о чем.

🔁 2. Бесконечная корутина рядом с ботом

Работа «следить за часами» никогда не заканчивается: проверила — подождала — проверила снова. В коде это бесконечный цикл с ожиданием внутри. Проверим, как он уживается с хэндлерами, на модели из модуля 3.

Создайте папку bg_lab рядом с прошлыми лабораториями, а в ней loop_demo.py:

import asyncio
import time

START = time.monotonic()


def log(text: str) -> None:
    print(f"[{time.monotonic() - START:4.2f}s] {text}")


async def reminder_loop() -> None:
    while True:
        log("фон: проверяю, кому пора")
        await asyncio.sleep(1)


async def handler(name: str, delay: float) -> None:
    await asyncio.sleep(delay)
    log(f"{name}: пришло сообщение")
    await asyncio.sleep(0.1)
    log(f"{name}: бот ответил")


async def main() -> None:
    task = asyncio.create_task(reminder_loop())
    await asyncio.gather(handler("Аня", 0.5), handler("Борис", 1.5))
    log("опрос закончен")


asyncio.run(main())

log() — знакомая по урокам 3.3 и 8.1 печать со временем от старта. reminder_loop() раз в секунду «проверяет расписание». handler() изображает хэндлер: сообщение пришло через delay секунд, ответ ушёл через 0.1. А gather() из двух хэндлеров играет роль опроса Telegram: пока он идёт, бот работает.

Запустите python loop_demo.py:

[0.00s] фон: проверяю, кому пора
[0.50s] Аня: пришло сообщение
[0.60s] Аня: бот ответил
[1.00s] фон: проверяю, кому пора
[1.50s] Борис: пришло сообщение
[1.60s] Борис: бот ответил
[1.60s] опрос закончен

Строки фона и хэндлеров перемешаны. Аня получила ответ через 0.1 секунды после сообщения, хотя рядом крутится бесконечный цикл. Цикл тоже не останавливался: проверка на 0.00 и на 1.00. Каждый await asyncio.sleep() отдаёт управление event loop, и тот переключается туда, где есть работа.

Обратите внимание на последнюю строку. Когда main() закончилась, asyncio.run() сам отменил оставшиеся задачи — и бесконечный цикл с ними. В боте так и будет: остановили бота — остановились напоминания.

Почему create_task(), а не await

Хочется написать проще: await reminder_loop(). Замените первую строку main() на эту и запустите:

[0.00s] фон: проверяю, кому пора
[1.00s] фон: проверяю, кому пора
[2.00s] фон: проверяю, кому пора
[3.00s] фон: проверяю, кому пора
<<TIMEOUT>>

Ни Аня, ни Борис не дождались ответа. await означает «дождись, пока закончится». Бесконечный цикл не закончится никогда, и до строки с gather() дело не дойдёт. В боте это значит: до start_polling() выполнение не дойдёт, и бот не ответит ни на одну команду.

asyncio.create_task() из урока 3.2 делает другое: ставит корутину в event loop и сразу возвращает управление. Цикл работает сам по себе, а main() идёт дальше.

await reminder_loop()                     →  ждать, пока цикл закончится (никогда)
task = asyncio.create_task(reminder_loop())  →  запустить цикл и идти дальше

Верните строку с create_task().

Зачем task =

Переменная task дальше нигде не используется. Её можно было бы не заводить — но так делать не стоит. Event loop хранит на задачу только слабую ссылку, которая не мешает Python удалить объект. Если других ссылок нет, задачу может удалить сборщик мусора посреди работы. Документация asyncio прямо советует сохранять результат create_task() в переменную.

🔑 Фоновая работа — через create_task():
Бесконечный цикл с await asyncio.sleep() внутри, запущенный через create_task(), работает рядом с хэндлерами и не мешает им. Результат create_task() сохраняем в переменную.

🕐 3. Раз в минуту

Время напоминаний в ПривычкаБоте — с точностью до минуты: 07:30, 21:00. Значит, проверять расписание чаще раза в минуту незачем. Но и asyncio.sleep(60) не совсем то, что нужно.

Пусть бот запустили в 07:29:42. Первая проверка — сразу, следующая через 60 секунд, в 07:30:42. Ещё через 60 — в 07:31:42. Проверка каждый раз приходит в середину минуты, а каждая проверка ещё и сама занимает время, поэтому сдвиг понемногу растёт.

Лучше спать не 60 секунд, а до начала следующей минуты:

await asyncio.sleep(60 - clock.now().second)
сейчас 07:29:42   →   60 - 42 = 18 секунд   →   проснёмся в 07:30:00
сейчас 07:30:01   →   60 - 1  = 59 секунд   →   проснёмся в 07:31:00

Проверки прилипают к началу минуты. Что такое clock.now(), разберём в разделе 6, пока это «сейчас».

🧩 4. Логика отдельно от цикла

Перед тем как писать проверку, решим, как мы будем её проверять. Если вся логика сидит внутри бесконечного цикла, проверка «пришло ли утреннее сообщение» выглядит так: запустить бота и ждать 07:30. Ошиблись — исправить и ждать до завтра.

Поэтому разделим. Цикл ничего не решает: он только узнаёт текущее время и передаёт его функции, а функция решает, кому и что отправить.

reminder_loop(bot)          →  каждую минуту: send_due(bot, сейчас)
send_due(bot, now)          →  кому пора на момент now — тем отправить

Главное здесь — что send_due() получает время аргументом, а не узнаёт сама. Тогда её можно вызвать с любым временем: «представь, что сейчас 07:30» — и посмотреть, что она отправит. Без ожидания утра.

Это та же идея, что в уроке 8.4: build_morning_text(user_id, day) получает дату аргументом и не зависит от сообщения. Функции, которые получают всё нужное через аргументы, легко проверять и легко вызывать из разных мест.

🔑 Время — аргументом:
Цикл знает, когда проверять. Функция знает, что делать в момент now. Функцию с временем в аргументе можно проверить для любого часа, не дожидаясь его.

🎯 5. Кому пора

Проверка идёт в начале каждой минуты. У привычки есть remind_time, например "21:00". Когда отправлять напоминание?

Попытка 1: время совпало

Первое, что приходит в голову: отправлять, когда текущее время равно времени привычки.

now.strftime("%H:%M") == remind_time

В обычный день это работает. Но представьте: в 20:59 бот перезапустили, на запуск ушло полторы минуты. Первая проверка — в 21:01. Время уже не равно "21:00", и сегодня Аня напоминания не получит. Так же пропадёт напоминание, если проверка в 21:00 задержалась: например, из-за медленного сервиса погоды утренняя рассылка заняла больше минуты.

Попытка 2: время прошло

Тогда наоборот: отправлять, если время привычки уже наступило.

remind_time <= now.strftime("%H:%M")

Сравнение строк здесь работает правильно: "07:05" < "07:30" < "21:00". Python сравнивает строки посимвольно, а все времена записаны одинаково, двумя цифрами. Это заслуга parse_time() из урока 6.3: она превращала «7:5» в «07:05». С записью «7:5» сравнение бы сломалось: "7:5" > "21:00", потому что "7" больше "2".

Но у второй попытки другая беда. Бота запустили в 22:00 — например, впервые, на новом сервере. Для каждой привычки этого дня время уже прошло, и бот разом пришлёт все напоминания с утра. Утреннее сообщение — в десять вечера.

Окно

Нужна середина: напоминание пора отправить, если его время наступило, но прошло не слишком много. Назовём этот запас CATCH_UP — 15 минут:

    21:00                    21:15
------|=========================|------------→  время
      ^ пора                    ^ поздно, пропускаем

планировалось  ≤  сейчас  <  планировалось + CATCH_UP

Перезапуск в 21:01 — напоминание догонит. Запуск в 22:00 — старые напоминания уже вне окна, лавины не будет. А что окно длиной 15 минут не даст отправить напоминание 15 раз подряд, разберём в разделе 7.

Сравниваем время, а не строки

«Плюс 15 минут» к строке не прибавить. Поэтому в окне сравниваем не строки, а объекты datetime. Из "21:00" и текущего момента получаем «сегодня в 21:00». Для этого у datetime есть метод replace(): он возвращает копию, в которой заменены указанные части.

now = datetime(2026, 11, 2, 21, 3, 27)
now.replace(hour=21, minute=0, second=0, microsecond=0)   →   2026-11-02 21:00:00

Секунды и микросекунды тоже обнуляем: иначе в копию перейдут 27 секунд из текущего времени. Прибавлять к datetime промежуток timedelta вы умеете с урока 7.1.

Эту проверку вы напишете в задаче 1 — функцию is_due(). Она войдёт в reminders.py без изменений.

🔑 Пора — это окно, а не точка:
Напоминание отправляется, если его время наступило не больше 15 минут назад. Так перезапуск бота не теряет напоминания и не присылает старые.

from datetime import datetime, timedelta

CATCH_UP = timedelta(minutes=15)


def is_due(remind_time: str, now: datetime) -> bool:
    hours, minutes = remind_time.split(":")
    planned = now.replace(
        hour=int(hours), minute=int(minutes), second=0, microsecond=0
    )
    return planned <= now < planned + CATCH_UP

🌍 6. Один часовой пояс для бота

В разделе 3 мы писали clock.now(), а не datetime.now(). Причина — в модуле 9 бот переедет на сервер. Посмотрим, чем это грозит.

Создайте в bg_lab файл tz_demo.py:

from datetime import datetime
from zoneinfo import ZoneInfo

print("datetime.now():           ", datetime.now().strftime("%H:%M"))
print("по Москве:                ", datetime.now(ZoneInfo("Europe/Moscow")).strftime("%H:%M"))
print("по Гринвичу (UTC):        ", datetime.now(ZoneInfo("UTC")).strftime("%H:%M"))

ZoneInfo("Europe/Moscow") — часовой пояс из встроенного модуля zoneinfo. datetime.now() с часовым поясом в скобках возвращает время в этом поясе. Без скобок — время того компьютера, на котором запущена программа.

Запустите python tz_demo.py. На компьютере в Москве:

datetime.now():            18:35
по Москве:                 18:35
по Гринвичу (UTC):         15:35

Первые две строки совпадают: компьютер живёт по московскому времени. А теперь та же программа на сервере. Серверы почти всегда настроены на UTC — время по Гринвичу, без поясов и переходов. Мы запустили её с часовым поясом сервера:

datetime.now():            15:35
по Москве:                 18:35
по Гринвичу (UTC):         15:35

datetime.now() на сервере отстаёт на три часа. Если бот сравнивает напоминания с ним, Аня получит утреннее сообщение в 10:30. А date.today() в хэндлерах сломается тише: с 21:00 до полуночи по Москве на сервере ещё вчера, и отметка на /today уйдёт во вчерашний день.

clock.py

Часы бота должны показывать одно время, где бы он ни работал. Соберём их в одном месте. Создайте в папке проекта clock.py:

"""Время бота: один часовой пояс для всех его часов."""
from datetime import date, datetime
from zoneinfo import ZoneInfo

TIMEZONE = ZoneInfo("Europe/Moscow")


def now() -> datetime:
    return datetime.now(TIMEZONE)


def today() -> date:
    return now().date()

Две функции на весь проект: now() — текущий момент, today() — сегодняшняя дата, обе по Москве. Если ваши пользователи живут в другом поясе, поменяйте одну строку TIMEZONE.

Теперь замените в handlers/habits.py все date.today() на clock.today(). Их шесть: в cmd_today, cmd_list, cmd_stats, switch_page, toggle_habit_from_list и cmd_morning. Поиск в VS Code (Ctrl+F) по date.today() найдёт все. И добавьте импорт:

Строку from datetime import date, timedelta не трогайте: date нужен в аннотациях, timedelta — в cmd_stats.

🧾 7. Не отправить дважды: таблица sent

Окно из раздела 5 длится 15 минут, а проверка идёт каждую минуту. Значит, условие is_due() будет истинным пятнадцать проверок подряд. Без защиты Аня получит пятнадцать утренних сообщений.

Боту нужно помнить, что он уже отправил сегодня. Держать это в памяти нельзя: перезапуск сотрёт её, и бот отправит всё ещё раз. Запишем в базу.

Шаг 1. Таблица

Добавьте в CREATE_TABLES в database.py, после таблицы users:

CREATE TABLE IF NOT EXISTS sent (
    user_id INTEGER NOT NULL,
    kind    TEXT    NOT NULL,
    day     TEXT    NOT NULL,
    UNIQUE (user_id, kind, day)
);
  • kind — что отправлено: "morning" для утреннего сообщения, "habit_3" для напоминания о привычке с номером 3;
  • day — за какой день, строкой "2026-11-02", как marked_date в таблице marks;
  • UNIQUE (user_id, kind, day) — одно сообщение одного вида одному пользователю в один день. Вторую такую строку база не примет.

Шаг 2. mark_sent()

Нужна функция, которая отвечает на вопрос «можно отправлять?» и сразу записывает ответ. Добавьте в конец database.py:

async def mark_sent(user_id: int, kind: str, day: date) -> bool:
    async with aiosqlite.connect(DB_PATH) as db:
        cursor = await db.execute(
            "INSERT INTO sent (user_id, kind, day) VALUES (?, ?, ?) "
            "ON CONFLICT DO NOTHING",
            (user_id, kind, day.isoformat()),
        )
        await db.commit()
    return cursor.rowcount == 1

ON CONFLICT DO NOTHING — младший брат ON CONFLICT DO UPDATE из урока 8.4: если такая строка уже есть, ничего не делать. А rowcount — знакомый по toggle_mark() из урока 7.2 счётчик затронутых строк.

первый вызов за день    →  строка вставлена   →  rowcount = 1  →  True: отправляй
повторный вызов         →  конфликт, пропуск  →  rowcount = 0  →  False: уже было

Проверка и запись — одним запросом. Если проверить отдельно («есть ли строка?»), а записать потом, между ними может вклиниться второй вызов — та же гонка, что с двойным нажатием «Сохранить» в уроке 6.4.

Сначала отметить, потом отправить

В send_due() порядок будет такой: mark_sent(), затем отправка. Если отправка не удастся, сообщение уже отмечено и повторно не уйдёт. Это осознанный выбор, как в уроке 8.3: не повторяем то, что не получилось. Пропущенное напоминание лучше, чем пятнадцать одинаковых.

Шаг 3. Два запроса для рассылки

Циклу нужны привычки всех пользователей, а для утреннего сообщения — список тех, у кого есть привычки. Добавьте в конец database.py:

async def get_all_habits() -> list[dict]:
    async with aiosqlite.connect(DB_PATH) as db:
        db.row_factory = aiosqlite.Row
        cursor = await db.execute(
            "SELECT id, user_id, name, remind_time FROM habits ORDER BY id"
        )
        rows = await cursor.fetchall()
    return [dict(row) for row in rows]
async def get_user_ids() -> list[int]:
    async with aiosqlite.connect(DB_PATH) as db:
        cursor = await db.execute(
            "SELECT DISTINCT user_id FROM habits ORDER BY user_id"
        )
        rows = await cursor.fetchall()

    user_ids = []
    for row in rows:
        user_ids.append(row[0])
    return user_ids

Это первые функции в database.py без user_id в аргументах: им нужны данные всех пользователей сразу. Вызывать их из хэндлеров не нужно — только из рассылки. DISTINCT убирает повторы: у Ани две привычки, но в списке она одна.

🔑 Отправленное помнит база:
UNIQUE в таблице sent и ON CONFLICT DO NOTHING в mark_sent() пропускают одно сообщение одного вида в день — при любом числе проверок и перезапусков.

🧪 Задание

Вопрос: В 07:30 Аня получила утреннее сообщение. В 07:31 бота перезапустили. Что произойдёт при проверке в 07:32?

  1. Ничего: is_due() вернёт True, но mark_sent() вернёт False — строка за сегодня уже есть ✅
  2. Аня получит сообщение второй раз: после перезапуска бот всё забыл
  3. Ничего: is_due() вернёт False, потому что 07:32 не равно 07:30
  4. Ошибка IntegrityError: строка с таким ключом уже есть

Отзыв на верный ответ:
Верно. Отметка лежит в базе и переживает перезапуск. А ON CONFLICT DO NOTHING превращает повторную вставку из ошибки в тихий rowcount = 0.

Подсказка при неверном ответе:
Где хранится отметка «уже отправлено» — в памяти или в базе? Попадает ли 07:32 в окно 07:30–07:45? Что делает ON CONFLICT DO NOTHING вместо ошибки?

Шаг 2. Модуль

Создайте в папке проекта reminders.py:

"""Напоминания: бот сам пишет пользователям по расписанию."""
import asyncio
import logging
from datetime import datetime, timedelta

from aiogram import Bot, html
from aiogram.exceptions import TelegramForbiddenError
from aiogram.types import InlineKeyboardMarkup

import clock
import database
import keyboards
import texts
from handlers.habits import build_morning_text

MORNING_TIME = "07:30"
CATCH_UP = timedelta(minutes=15)

logger = logging.getLogger(__name__)


def is_due(remind_time: str, now: datetime) -> bool:
    hours, minutes = remind_time.split(":")
    planned = now.replace(
        hour=int(hours), minute=int(minutes), second=0, microsecond=0
    )
    return planned <= now < planned + CATCH_UP


async def deliver(
    bot: Bot,
    user_id: int,
    text: str,
    markup: InlineKeyboardMarkup | None = None,
) -> None:
    try:
        await bot.send_message(user_id, text, reply_markup=markup)
    except TelegramForbiddenError:
        logger.warning("Пользователь %s заблокировал бота", user_id)


async def send_due(bot: Bot, now: datetime) -> None:
    day = now.date()

    if is_due(MORNING_TIME, now):
        for user_id in await database.get_user_ids():
            if await database.mark_sent(user_id, "morning", day):
                text = await build_morning_text(user_id, day)
                await deliver(bot, user_id, text)

    for habit in await database.get_all_habits():
        if not is_due(habit["remind_time"], now):
            continue

        user_id = habit["user_id"]
        done_ids = await database.get_done_ids(user_id, day)
        if habit["id"] in done_ids:
            continue

        if await database.mark_sent(user_id, f"habit_{habit['id']}", day):
            await deliver(
                bot,
                user_id,
                texts.REMINDER.format(name=html.quote(habit["name"])),
                keyboards.reminder_keyboard(habit["id"], habit["name"]),
            )


async def reminder_loop(bot: Bot) -> None:
    while True:
        await send_due(bot, clock.now())
        await asyncio.sleep(60 - clock.now().second)

Разберём по функциям.

is_due()

Ваша функция из задачи 1, с аннотациями. CATCH_UP и MORNING_TIME — константы модуля, рядом.

deliver(): отправка без message

В хэндлерах мы писали message.answer(): у сообщения есть чат, туда и ответ. У рассылки сообщения нет, поэтому отправляет сам бот: bot.send_message(user_id, text). В личной переписке номер чата равен номеру пользователя (урок 7.4), так что user_id из базы подходит.

Почему отправка завернута в try? Пользователь может заблокировать бота. Тогда Telegram отвечает отказом, и aiogram поднимает TelegramForbiddenError. Мы проверили, что будет без try, если Аня заблокировала бота:

  ...

    await deliver(bot, user_id, text)
  File "reminders.py", line 36, in deliver
    await bot.send_message(user_id, text, reply_markup=markup)
  ...
aiogram.exceptions.TelegramForbiddenError: Telegram server says - Forbidden: bot was blocked by the user

Исключение вылетело из send_due(), и рассылка оборвалась на Ане. Борис стоит в списке после неё и не получил ничего. Один заблокировавший бота пользователь оставил без сообщений всех, кто идёт за ним. Поэтому ловим ровно этот отказ, пишем в лог и идём дальше — правило урока 2.6.

С try в deliver() мы проверили обратный случай: бота заблокировал Борис. Аня получила своё сообщение, а в терминале бота осталась строка лога:

send_due(): кому что отправить

Две части, по одной на вид сообщения.

Утреннее. Если MORNING_TIME попало в окно — для каждого пользователя с привычками: mark_sent() пропустил — собрать текст и отправить.

По привычкам. Для каждой привычки: не пора — дальше. Уже отмечена сегодня — дальше: напоминать о сделанном незачем. Иначе — mark_sent() и отправка с кнопкой. Название привычки проходит через html.quote(), как везде, где его пишет пользователь.

Порядок проверок выбран не случайно: сначала самые дешёвые. is_due() — вычисление без базы, и большинство привычек отсеется на нём. Запрос отметок и запись в sent — только для тех, кому действительно пора.

reminder_loop(): цикл

Две строки из разделов 2–4: проверить на текущий момент и спать до следующей минуты. Первая проверка — сразу при запуске, поэтому пропущенное за время перезапуска догоняется без ожидания.

💡 Забегая вперёд:
deliver() ловит одну ожидаемую ошибку. Но если внутри send_due() случится неожиданная — например, база окажется заблокированной, — исключение вылетит из цикла, и задача молча завершится. Бот продолжит отвечать на команды, а напоминания прекратятся. Как это заметить и как это предотвратить, разберём в уроке 9.4.

"""Напоминания: бот сам пишет пользователям по расписанию."""
import asyncio
import logging
from datetime import datetime, timedelta

from aiogram import Bot, html
from aiogram.exceptions import TelegramForbiddenError
from aiogram.types import InlineKeyboardMarkup

import clock
import database
import keyboards
import texts
from handlers.habits import build_morning_text

MORNING_TIME = "07:30"
CATCH_UP = timedelta(minutes=15)

logger = logging.getLogger(__name__)


def is_due(remind_time: str, now: datetime) -> bool:
    hours, minutes = remind_time.split(":")
    planned = now.replace(
        hour=int(hours), minute=int(minutes), second=0, microsecond=0
    )
    return planned <= now < planned + CATCH_UP


async def deliver(
    bot: Bot,
    user_id: int,
    text: str,
    markup: InlineKeyboardMarkup | None = None,
) -> None:
    try:
        await bot.send_message(user_id, text, reply_markup=markup)
    except TelegramForbiddenError:
        logger.warning("Пользователь %s заблокировал бота", user_id)


async def send_due(bot: Bot, now: datetime) -> None:
    day = now.date()

    if is_due(MORNING_TIME, now):
        for user_id in await database.get_user_ids():
            if await database.mark_sent(user_id, "morning", day):
                text = await build_morning_text(user_id, day)
                await deliver(bot, user_id, text)

    for habit in await database.get_all_habits():
        if not is_due(habit["remind_time"], now):
            continue

        user_id = habit["user_id"]
        done_ids = await database.get_done_ids(user_id, day)
        if habit["id"] in done_ids:
            continue

        if await database.mark_sent(user_id, f"habit_{habit['id']}", day):
            await deliver(
                bot,
                user_id,
                texts.REMINDER.format(name=html.quote(habit["name"])),
                keyboards.reminder_keyboard(habit["id"], habit["name"]),
            )


async def reminder_loop(bot: Bot) -> None:
    while True:
        await send_due(bot, clock.now())
        await asyncio.sleep(60 - clock.now().second)

import asyncio
