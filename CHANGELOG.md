## [Unreleased]

### Добавлено

- Локальные версии урока: `stepik_save_version`, `stepik_list_versions`, `stepik_restore_version` (весь файл или один шаг по `step_id`; без `apply=True` только diff, с `apply=True` текущий файл сначала сохраняется новой версией). Правила режима правки просят сохранять версию перед правкой.
- `stepik_run_examples`: запуск примеров ```` ```python ```` из урока в отдельном процессе без секретов сервера, с пустым вводом и ограничением 5 секунд; вывод сравнивается с блоком ```` ```text ```` после примера. Куски кода из середины программы (`NameError`, `return` вне функции, `elif` без `if`) помечаются `fragment` и в проблемы не попадают. На уроке 5.2 курса 266999 (копия): 75 примеров, 3 совпали с выводом в тексте, ложных проблем нет.
- `stepik_lesson_outline`: оглавление урока со строками файла каждого шага, чтобы агент читал длинный урок по частям.
- `stepik_check_course`: `stepik_check_lesson` по всем скачанным урокам, сводка в ответе и таблица в `sessions/…-course-check.md`. `stepik_check_lesson` работает и без карты курса (без поиска забегания вперёд).
- `stepik_glossary`: словарь терминов из карты в генерируемый `GLOSSARY.md`, термины, введённые дважды, и нежелательные имена из таблицы «Термины и имена» в `COURSE_STYLE.md`, найденные в уроках.
- `stepik_preview_lesson`: HTML-предпросмотр урока рядом с файлом урока, задания без ответов.
- `stepik_comment_digest`: вопросы и жалобы учеников по шагам из сохранённого `.comments.md`, без имён.
- `stepik_task_mistakes`: неверные решения задания, сгруппированные по отзыву Stepik или по одинаковому ответу (данные API ещё не сверены с интерфейсом).
- `stepik_save_metrics` и `stepik_compare_metrics`: снимки показателей заданий урока в `metrics/` и сравнение «до и после» правки.
- `stepik_stage_lesson`: копия урока черновиком в папку тестового курса для проверки через `stepik_plan_create_lesson` и `stepik_plan_push`.
- Ученик-тестировщик двух уровней: `level="novice"` (полный новичок) и `level="experienced"` (ученик с опытом, ищет повторы и медленный темп).
- Режимы работы с агентом: «скачать тексты уроков», «править курс вместе» и «пройти курс учеником». Инструкции сервера просят агента предложить выбор, если задача не названа; режимы доступны MCP-подсказками `stepik_start`, `stepik_download`, `stepik_edit`, `stepik_student`, а `stepik_second_opinion` даёт второй взгляд другой модели на отчёт.
- Ученик-тестировщик: `stepik_start_editing(mode="student")` и шаблон `rules/STUDENT_TEST_RULES.md` с критериями (порядок изложения, темы «с потолка», отсылки, термины, примеры, задания, тесты с выбором, длина шагов) и форматом находок с тяжестью «блокер / мешает / мелочь». Режим правки начинает с находок ученика.
- `stepik_check_lesson`: урок по карте курса без запросов к Stepik — термины, которые карта относит к более поздним урокам (отдельно в заданиях), отсылки к другим урокам и модулям, «очевидно» и «как известно», длинные шаги, задания без теории перед ними. На уроке 5.2 курса 266999 находит 15 отсылок (к уроку 5.1 и к модулям 4 и 7), подзаголовки «Шаг N» не считаются.
- `stepik_course_status`: состояние уроков по карте, отчёты в `sessions/`, уроки с наибольшим числом сохранённых комментариев, последняя передача и что делать дальше. `stepik_start_editing` тоже называет последнюю передачу.
- Короткие замечания в чате и пакетная правка: в чат — номер, место, суть и буквы вариантов; принятые пункты вносятся все сразу, а их статус отмечается в отчёте; затем один план публикации.
- `stepik_start_editing`: готовит папку курса к совместной правке и создаёт карту курса `COURSE_LOGIC.md` (цель курса, модули, что ученик узнаёт в каждом уроке, на что урок опирается, термины, задания, состояние). Карта не перезаписывается; ответ называет уроки, которых в ней нет или у которых она не заполнена.
- Шаблон `DECISIONS.md` для решений автора. В `rules/REVIEW_RULES.md` у замечания появились номер, точная цитата и варианты A/B/C (замена, вставка, изменение задания), а автор отвечает коротко: «1A, 3 пропусти». Шаблоны появляются только в новых папках курса и там, где файла ещё нет.
- Переименование урока: `title:` во frontmatter файла сравнивается с названием на Stepik, `stepik_plan_push` предлагает `RENAME`, `stepik_apply_push` меняет название (`PUT lessons`). Название, изменённое на Stepik после скачивания, не затирается.
- `stepik_plan_move_lesson`: перестановка урока внутри модуля через plan/apply.
- Формат урока 6: блок кода внутри пункта списка записывается с отступом под пунктом и собирается обратно внутрь пункта. Раньше список при правке шага разрывался на части. На курсе 241862 вёрстку при правке меняют 7 шагов из 139 (было 17), на 276752 — 4 из 123. Файлы прежних форматов переводит `stepik_upgrade_lesson`.
- Папка курса получает шаблоны правил `COURSE_STYLE.md`, `rules/` (текст, структура урока, задания, код, рецензия) и `sessions/HANDOFF_TEMPLATE.md`; `AGENTS.md` описывает редакторский процесс: прочитать правила → рецензия в `sessions/` → правки только согласованного → план публикации → передача работы. Существующие файлы не перезаписываются.
- `stepik_plan_delete_lesson`: удаление урока через plan/apply с `confirm_delete=[lesson_id]`; шаги сохраняются в `snapshots/`, локальный файл остаётся.

### Исправлено

- Урок, вставленный в середину модуля, вставал после соседа с той же позицией: Stepik не сдвигает соседние уроки. После вставки, перестановки и удаления позиции уроков модуля выставляются явно. Проверено на курсе 241862.

## [0.4.0] — 2026-11-02

Полный цикл с курсом: скачать весь курс, обновлять уроки со Stepik, создавать уроки, править шаги без потери оформления (формат 5), переводить старые файлы в новый формат. Проверено на настоящем Stepik.

### Добавлено

- Формат урока 5: правка шага сохраняет оформление автора. Стиль блока кода пишется в строке ограды (```` ```python {style="background:#2d3436;"} ````), абзацы и заголовки со стилем (центрирование) — HTML-ом, размеры картинки — `![подпись](адрес){width="870"}`, ссылки — `[текст](адрес)`, второй перенос строки подряд — строкой `<br>`, неразрывный пробел — `&nbsp;`. Текст в начале строки, похожий на список, заголовок или цитату («- пункт» после переноса), экранируется. На курсе 266999 правка меняет структуру у 1 шага из 440 (было 195) и теряет оформление у 4 (было 275).
- `stepik_plan_create_lesson`: план создания урока из локального черновика (название из `title:` или «# …», шаги — `<!-- new_step -->`). `stepik_apply_push` создаёт пустой урок, привязывает его к модулю на нужную позицию, записывает ID в черновик и `.course.json` и сохраняет прежний черновик в `snapshots/`; шаги затем публикуются через `stepik_plan_push`. Проверено на тестовом курсе 241862: создание, публикация шагов, правка, откат.
- `stepik_pull_course`: весь курс одним вызовом — все уроки со всеми типами шагов и описание курса в `COURSE_INFO.md`. Структура курса обновляется: новые уроки добавляются, у известных остаются прежние пути, удалённые и перемещённые на Stepik уроки названы в ответе. Существующие файлы уроков не перезаписываются.
- `stepik_refresh_lesson`: обновление файла урока со Stepik по трём версиям (база, файл, Stepik). Шаги, изменённые только на Stepik, заменяются; правки автора остаются; при конфликте версия Stepik сохраняется рядом в `<урок>.stepik-<время>.md`, а `resolved` принимает её базой после ручного переноса. Новые шаги Stepik вставляются на свои места. Без `apply=True` ничего не пишет; прежний файл сохраняется в `snapshots/`.
- Формат урока 4: таблицы сохраняются в файле урока HTML-ом как есть, спойлеры — блоком `<details>` / `<summary>` с обычным Markdown внутри. Правка шага с таблицей или спойлером больше не теряет их, и план не предупреждает о потере. Файлы формата 3 читаются прежним разбором; правка шага, который в них выглядит иначе, не публикуется, а план просит скачать урок заново.
- `stepik_upgrade_lesson`: переводит урок, скачанный старой версией, в текущий формат без потери правок. Нетронутые шаги записываются заново, правки автора переносятся на новую запись шага построчным слиянием (`EDITED_MERGED`); если правка задевает строки, которые меняет формат, или шаг без исходника менялся на Stepik после скачивания, ничего не записывается и шаг попадает в `conflicts`. Прежний файл — в `snapshots/`. На копиях курсов 266999 и 276752: 38 уроков переведены, 4 правки с иллюстрациями в уроке 6.1 перенесены, 3 урока, изменённые на Stepik после скачивания, остались для повторного скачивания.
- Живые проверки `tests/test_live.py`: авторизация, «скачать → собрать обратно» по тестовому курсу, правка → публикация → обновление второй копии → откат на уроке `2676604` курса 241862. Запускаются только с `STEPIK_LIVE=1` и ключами в `.env`; без них пропускаются.

### Изменено

- Ошибки всех инструментов возвращаются JSON-ом `{"status": "error", "code", "message"}`: код берётся из начала сообщения (`WRITE_NOT_ALLOWED`, `LOCAL_CHANGED`, …) или из HTTP-статуса (`NOT_FOUND`, `CONFLICT`, …); `CONFIG_MISSING` — не заданы ключи Stepik.
- Папка курсов по умолчанию — `C:\Courses` в Windows и `~/Courses` в Linux и macOS; `COURSE_WORKSPACE_ROOT` больше не обязательна. Описания инструментов не называют `C:\Courses`.
- Все инструменты размечены аннотациями MCP: чтение — `readOnlyHint`, сохранение в папку курса — неразрушающая запись.
- В папке курса рядом с `AGENTS.md` создаётся `CLAUDE.md` со строкой `@AGENTS.md`.

### Исправлено

- `<strong>Вопрос: </strong>` с пробелом или неразрывным пробелом внутри выгружался как `**Вопрос: **` и при правке шага публиковался звёздочками: пробел выносится за звёздочки.
- `<em><strong>x</strong></em>` собирался обратно в теги, вложенные крест-накрест; `***x***` теперь жирный курсив.
- Перенос `<br>` внутри пункта списка терялся при сборке.

## [0.3.0] — 2026-11-02

Публикация на Stepik через plan/apply: текст, картинки, задания, удаление и перестановка шагов, откат, удаление комментариев.

### Добавлено

- Публикация текстовых шагов и картинок: `stepik_plan_push` строит план и diff, ничего не отправляя, а `stepik_apply_push` публикует его после подтверждения автора. Можно менять существующие текстовые шаги и добавлять новые (метка `<!-- new_step -->`). Локальные картинки загружаются на Stepik как вложения урока.
- Защита записи: список курсов `ALLOWED_WRITE_COURSES` (по умолчанию пуст), проверка принадлежности урока курсу по API, отказ при изменении файла или урока на Stepik после плана, снимок урока в `snapshots/`, журнал `logs/stepik-write.log`, предупреждение о ссылках и оформлении, которые потеряются при публикации.
- Аннотации MCP: `stepik_apply_push` помечен как разрушающий, `stepik_plan_push` — как только читающий Stepik.
- 18 тестов публикации и Markdown → HTML. Публикация проверена на тестовом курсе 241862.
- Формат урока 2: задания хранятся как условие в Markdown и YAML-блок настроек (`steps.py`). Рядом с уроком сохраняются исходники шагов `.stepik/steps/<id>.json`; публикация сравнивает правку с ними и не затирает изменения, сделанные на Stepik после скачивания.
- `stepik_check_roundtrip`: проверка «скачать → собрать обратно» для всего курса. 683 из 683 шагов трёх курсов автора проходят.
- `ALLOWED_WRITE_COURSES=*`: запись в любой курс, где аккаунт токена автор или преподаватель.

- Публикация заданий: правки и новые шаги `choice`, `string`, `number`, `matching`, `sorting`, `free-answer` и `code`. Задание проверяется до отправки; шаги, которые уже решали ученики, требуют `confirm_steps` при применении.
- Локальный прогон эталонного решения задачи на код (`solution:` в YAML) на всех тестах перед публикацией.
- `stepik_rollback_lesson`: план возврата урока к снимку, применяется через `stepik_apply_push`. Удалённые шаги откат создаёт заново.
- Удаление шагов меткой `<!-- delete_step: N -->`: применение требует `confirm_delete` с точным списком шагов.
- Удаление комментариев: `stepik_plan_delete_comments` и `stepik_apply_delete_comments` с фильтром по тексту, автору и уроку, подтверждением точного числа и копией удалённого в `snapshots/`.
- `all_in_lesson` в `stepik_plan_delete_comments`: все комментарии одного урока, любых авторов, с ответами и комментариями без текста (только картинка). План показывает разбивку по авторам; ответы удаляются раньше корня ветки.

### Исправлено

- Новый шаг в середине урока вставал после следующего шага: Stepik не сдвигает соседей при создании. `stepik_apply_push` после записи сверяет порядок шагов с файлом и выставляет позиции (операция `move` в журнале). План, который только переставляет шаги, теперь публикуется (`MOVED`), а не отклоняется.
- Цитата с переносом строки (`**Заголовок:**` и текст на следующей строке без `>`, как её пишет загрузчик) публиковалась как цитата из одного заголовка, а текст выпадал из рамки отдельным абзацем. Строка без `>` после текста цитаты теперь продолжает цитату, перенос `<br>` сохраняется.

- Формат урока 3: цитаты (врезки) выгружаются целиком, каждая строка с `>`, внутри сохраняются абзацы, переносы, списки и код. Файлы формата 2 по-прежнему читаются и сравниваются прежним разбором; правка шага, который в старом файле выглядит иначе, не публикуется, а план просит скачать урок заново.
- Жирный и курсив вокруг кода (`**`await`**`, `*курсив `x`*`) публиковались звёздочками: пары `**` и `*` не искались через код.
- План публикации предупреждает, если после сборки из Markdown изменится вложенность блоков шага; `stepik_check_roundtrip` считает такие шаги (`steps_changing_structure_on_edit`).

- Снимки двух публикаций в одну секунду больше не конфликтуют по имени файла.

- Пункты списков с `<p>` внутри (так их сохраняет редактор Stepik) больше не превращаются в пустые `- `. Старые файлы уроков сравниваются прежним разбором, поэтому неизменённые шаги в них не попадают в план.
- Два блока кода подряд: у второго терялась открывающая ```, и в файле урока всё ниже считалось кодом, включая метки следующих шагов. Теперь каждый блок кода закрыт, разметка внутри `<pre>` не выводится, буквальные ``` в тексте экранируются. В старых файлах метки шагов ищутся без учёта оград.
- Шаг старого файла без исходника, который меняли на Stepik после скачивания (`update_date` позже `fetched_at`), больше не попадает в план: иначе публикация удалила бы правку, сделанную на Stepik.

## [0.2.0] — 2026-09-23

### Изменено

- Код разложен в устанавливаемый пакет `stepik_mcp` (`client`, `render`, `feedback`, `analytics`, `workspace`, `server`). Команды запуска: `stepik-mcp` и `python -m stepik_mcp`.

- `pyproject.toml`, CI на GitHub Actions (Windows и Linux, Python 3.12–3.13), линтер ruff.
- README с подключением к Claude Code, Claude Desktop и OpenCode; `AGENTS.md` и `CLAUDE.md` для агентов, работающих над репозиторием.

### Удалено

- Старый HTTP-мост `stepik_bridge.py` с токеном в URL. Режим `--http` MCP-сервера сохранён.
- Резервные копии `*_backup.py` и архив `stepik_mcp_opencode_bundle.zip`. Они остались в первом коммите истории.

### Миграция

Если клиент запускал `python stepik_mcp.py`, замените команду на `python -m stepik_mcp` после `pip install -e .`, или на путь к `stepik-mcp` в `.venv`.
